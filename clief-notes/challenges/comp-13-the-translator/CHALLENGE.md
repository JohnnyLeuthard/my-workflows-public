🎯 THE CHALLENGE

Build a folder-based AI translator that takes one kind of work and turns it into another kind of work.

Same shape in, same shape out, every time.

This is not a summarizer. This is not a writer. It's a converter with a contract.

🔁 PICK YOUR CONVERSION

The conversion is yours to choose. Pick a pair of formats you actually move between.

The translator's job is to take input in format A and reliably produce output in format B — with the same structure, the same fidelity, and the same rules applied on every run.

🗂️ THE METHODOLOGY

If this is your first comp, welcome. Here's what you need to know:

This week (and every week) you're learning interpretable context methodology. Folders as architecture. Each file does one job well.

Your translator is a folder with these essentials:

📄 identity.md (who the translator is, what it converts from and to)  
📐 rules.md (how the conversion works — the contract)  
💬 examples.md (paired input/output showing a correct conversion)  
📚 reference/ (schemas, format specs, mappings the translator uses)  
📖 README.md (how to use it)  

Drop the folder into a Claude project. Claude becomes the translator. Reusable. Shareable. Portable.

🔥 THE ANGLE THIS WEEK

The contract is the whole assignment.

A translator that produces a different shape each time it runs has failed, even if each individual output reads well. The value is predictability: hand it the same input twice and you get the same output twice. Hand it a new input of the same type and you get the same structure back.

Your rules.md is where you write the contract.

📝 HOW TO SUBMIT

Submit one translator folder that someone could drop into a Claude project and get consistent, predictable outputs from.

Drop a public GitHub repo link in the comments, plus 2-3 sentences on what your translator converts and who it's for.
